# خطة دمج رفع الوسائط (صور/فيديو) في نظام Feedback

## القرارات النهائية
1. **الرفع عبر `ApiClient`** — أضيف method جديد `uploadFile()` للحفاظ على تنظيم "كل الـ HTTP في مكان واحد". يدعم `FormData` + `onSendProgress` لتتبّع تقدّم الرفع، ويُرجع `Either<Failure, dynamic>` بنفس النمط المعتاد.
2. **Picker:** `image_picker` — زر `+` يفتح المعرض مباشرة.
3. **العرض:** `Image.network` للصور + إعادة استخدام `NotificationVideoPlayer` الموجود (`video_player: ^2.9.2`) للفيديو.
4. **القيود:** صور (jpeg/png/webp/gif ≤10MB) + فيديو (mp4/webm/mov ≤50MB) + max 5 ملفات — تُطبّق في الـ controller.

## الملفات المُعدَّلة

### 1. `lib/core/services/api_client.dart` ⭐ (إضافة method)
أضيف `uploadFile` بعد `request`:
```dart
/// رفع ملف عبر multipart/form-data. لرفع الوسائط لـ R2.
/// يُرجع Either<Failure, dynamic> كالعادة. url الرجوع في response.data['url'].
Future<Either<Failure, dynamic>> uploadFile({
  required String endpoint,
  required FormData data,
  Map<String, String>? headers,
  void Function(int sent, int total)? onSendProgress,
  bool? printResponse = false,
}) async {
  try {
    final response = await _dio.post(
      endpoint,
      data: data,
      options: Options(headers: headers),
      onSendProgress: onSendProgress,
    );
    if (printResponse!) log('Upload response: ${response.data}', name: 'ApiClient');
    return Right(response.data);
  } on DioException catch (e) {
    log('Upload DioException: ${e.message}', name: 'ApiClient');
    return Left(ErrorHandler.handle(e).failure);
  } catch (e) {
    log('Upload error: $e', name: 'ApiClient');
    return Left(DataSource.DEFAULT.getFailure());
  }
}
```
ملاحظة: `_dio` له `baseUrl: raw.githubusercontent.com` لكن Dio يتجاهل `baseUrl` عند تمرير URL مطلق في `endpoint` (نمرّر `https://feedback-api.../upload`).
